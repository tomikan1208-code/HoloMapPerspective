# GPU版0.5.1の不具合調査と検証

2026年11月7日に実施しました。

## 原因と修正

0.5.0は、裏面を見た際に保存した空白画像を、再び表へ回った際のGPU描画では更新していませんでした。同じ更新内の最初のタイルだけがGPU画像を受け取り、後続タイルは保存済みの空白を返す状態になります。従来版を別のPaperサーバーで動かし、この症状が発生することを確認しました。

また、各面のGPU処理が別々だったため、視点位置や動画の時刻が面ごとにずれ、タイルの送信中にも結果が切り替わる可能性がありました。0.5.1では1人・1表示につき6面をひとまとめに描き、全結果が揃ってから公開します。タイルは同じサーバーtickの間、同一の画像セットを参照します。待機中のジョブは処理開始時に新しい視点を使います。

GPUシェーダーの微分から作った法線が観察方向により反転し、上下から見たときに色が変わる問題も修正しました。モデルの三角形の向きに基づいて陰影を決めます。

## 環境と結果

- Windows 11、Java 25.0.1、Paper 26.3 build 243、正式API `26.3.build.243-stable`。
- NVIDIA GeForce RTX 3050、ModernGL 5.13.0。ソフトウェア描画での代用はしていません。
- Gradle build、JUnit 11件、GPU通信プロトコルテスト：成功。
- 旧0.5.0の実Paper＋GPUテスト：裏から表へ戻るとタイル間で画像が違うことを検出して失敗。
- 0.5.1の同テスト：76視点、1,668アサーションで成功。
- 4×4×4（96地図）のデモを斜めから見て3面を描く条件：5秒間で約19.97回/秒の完了画像更新。地図の更新呼出し9,600回。
- 直接描いた3Dモデルと6枚の地図面に再投影した像を比較：デモ222視点、Sparxie222視点、いずれも成功。
- 幾何比較では透明領域・モデル内部の欠け・平坦な色領域・像の重心を確認。低解像度の地図による境界1pxの差を除き、内部の欠け0、平坦な領域の色不一致0。256×256の比較画像で重心差は最大約0.68pxでした。

検証結果は `docs/verification-results/gpu-0.5.1/` に保存しています。GPU/Paperテストはユーザーのワールドではなく、`build/gpu-verification-server` の専用ワールドで実施しました。

## サーバーへの反映

承認後にワールドを保存して停止し、0.5.1のJARとGPUスクリプトを反映して再起動しました。Paperのプラグイン版表示は0.5.1、GPUはRTX 3050のREADY、Minecraftプロトコルによる照会も成功しています。

- 反映前にワールド753ファイル（約13.8MB）と、旧JAR、GPUスクリプト、設定類をバックアップしました。
- `config.yml` と `displays.yml` は反映前後のSHA-256が一致。停止時点で設置済み表示は0件、`next-id: 24` であり、その状態を維持しています。
- 配置JARのSHA-256：`94d7470a96c80c75f2dac2d814214b0e3dfba3f48f1fbdb7e34f211bb0d1f1f5`。
- 起動スクリプトはプラグインJARの版を自動判定するよう更新しました。

## 「その場に浮いている」見え方の範囲

静止した同一視点からの投影位置は、直接描いた3Dモデルと一致することを上記比較で確認しました。ただし、この方式がクライアントへ送るのは2Dの地図画像です。実モデルの奥行きや衝突形状を送るものではありません。雨や他の物との前後関係、展示空間の内部からの見え方は実際の3Dモデルと同じにはなりません。

視点をサーバーで取得してからGPUで描き、地図として届けるまでの遅れも残ります。サーバーで取得した目の位置は、画面側の補間・歩行時の揺れを含む実際のカメラ位置と完全には一致しません。面の更新ずれは修正しましたが、移動中の固定感まで無遅延になるという確認ではありません。

Minecraftクライアントの画面操作機能が利用できず、今回も実際のゲーム画面の目視確認と受信後の表示fps測定は行っていません。約19.97fpsはGPU画像セットの完了頻度で、クライアントの表示fpsではありません。画面の地図更新パケットが同時に適用されることも、この検証では確認していません。

## 再検証

```powershell
$env:JAVA_HOME = 'C:\Program Files\Java\jdk-25'
.\gradlew.bat build gpuVerificationJar
python tools\test_gpu_protocol.py
python tools\test_gpu_geometry.py --mesh <対象の.hmesh> --report build\gpu-geometry.json
```

幾何比較にはModernGLとNumPyを使います。`HoloMapGpuVerifier` は **専用テストサーバーのみ**で使用し、`-Dholomap.gpu.verification=true` とワールド名 `holomap_gpu_test` が必須です。テスト用表示を作り、検証完了後はサーバーを停止します。通常サーバーへ配置しないでください。

参考：[OpenGLの投影とクリッピング](https://wikis.khronos.org/opengl/Vertex_Post-Processing)、[Paperの目の位置API](https://jd.papermc.io/paper/26.3/org/bukkit/entity/LivingEntity.html)。
